# 用户音色库

设置 → 语音 → 我的音色库，可以导入、试听、选择、重命名、导出和删除本机音色。

## 参考录音音色

选择一段 1–30 秒、8–96 kHz、16 位 PCM WAV，可用单声道或双声道。建议使用 5–15 秒的单人清晰讲话，减少音乐、回声、杂音。填写名称；录音中实际说出的文字可选，也可同时选择 UTF-8 TXT 文件。没有文字时使用音色特征模式；提供准确文字可提高还原效果。

参考音色复用 Qwen3-TTS-12Hz-0.6B-Base，支持中文和英文输出。v0.1.6 可在“语音资源”中下载录音创建音色引擎及基础模型，无需手动配置。选择“从录音创建音色”后，应用实际调用模型生成样音，成功后保存；生成失败会清理本次音色。也可以先导入录音包，缺少引擎时仍可保存、重命名、导出或删除。

创建的是可分享的参考音色包，使用同一个基础模型恢复声音；不训练或导出新的 Piper ONNX 权重。建议 16 GB 内存，CPU 首次加载和生成可能需要数分钟。录音和生成都在本机完成。

导入后先试听，再点击“用于中文朗读”或“用于英文朗读”。试听不会改动已保存的选择。中文和英文可以选择同一个音色，也可以分别选择。原生后台唤醒和连续对话复用同一个选择；重启后按已保存设置恢复。

首次加载模型可能等待几十秒，CPU 更慢。CUDA 环境支持 PCM 流式；CPU 环境使用完整 WAV 播放。跨语言音色效果取决于录音和模型，建议分别试听中文、英文。

## Piper 模型音色

同时选择配套的 `.onnx` 和 `.onnx.json`。第一版支持配置声明为中文或英文、使用 espeak 音素的 Piper 模型。导入时检查配置，并在 Piper 已安装时实际加载验证；多个音色按不同模型分别加载，最多保留四个闲置用户后端缓存。

多说话人模型可填写 speaker ID；单说话人模型填写 0。语言取自模型配置，不能把英文模型声明成中文模型使用。朗读使用 WAV 接口。

## 分享与管理

导出得到 `.jvoice` 文件。它是版本为 1 的 ZIP 容器，包含 manifest 和录音/模型文件。别人导入同一个文件会得到自己的安装 ID，不覆盖内置声音或其他用户音色。参考录音包不包含 Qwen 基础模型，因此较小。

每个音色独立保存在 `<OPENJARVIS_HOME>/data/voice-packs/user-<UUID>/`。本机默认根目录为 `D:\Jarvis`。共享模型在 `OPENJARVIS_RESOURCE_ROOT`；用户音色跟随用户状态目录，可以随便携客户端移动。

删除前先切换已选择的音色。后台仍保存该音色或正在合成时，接口拒绝删除并说明原因。重命名不影响安装 ID、选择或音色内容。

管理接口仅支持本机客户端，并校验来源；第一版没有开放远程朋友网关的多用户上传功能。GPT-SoVITS、RVC、任意 `.pth/.pt/.ckpt` 文件和 MP3 参考录音尚不支持。

## 包格式

```json
{
  "schema_version": 1,
  "name": "我的助手声音",
  "kind": "reference",
  "engine": "qwen3-tts",
  "engine_model": "Qwen3-TTS-12Hz-0.6B-Base",
  "languages": ["zh", "en"],
  "reference_language": "zh",
  "embedding_only": true,
  "assets": {"audio": "reference.wav", "transcript": "reference.txt"}
}
```

Piper 使用 `kind: piper-model`、`engine: piper`、`speaker_id: 0` 和 `assets: {"model":"voice.onnx","config":"voice.onnx.json"}`。音色名称必填；原始文件导入由应用生成 manifest。

`embedding_only: true` 允许 `reference.txt` 为空；旧包省略此字段时继续要求准确对应文字。两种包都能在 v0.1.6 导入和使用。

上传总大小最多 256 MB，WAV 最多 12 MB，配置/TXT 最多 256 KB。ZIP 最多 16 个条目，展开总大小最多 256 MB；拒绝路径穿越、符号链接、加密包、重复和未声明文件、异常压缩比例。安装使用独立临时目录，验证成功后原子发布；失败不修改当前音色。

## 验证与本机启用

前端生产资源已经构建到 `src/openjarvis/server/static`。已运行的 Python API 和 Qwen worker 需要重新启动以加载新代码；仅隐藏托盘窗口不会重启后台。

本机可执行 `scripts/activate_voice_packs.ps1` 启用更新：脚本要求后台监听已关闭、语音生成空闲，核对端口对应的进程路径与命令后才重启 API 和语音服务。它不删除或改动用户数据。

2026-10-06 本机已执行启用，运行中的 `/v1/speech/packs` 和 worker `reference_api: 1` 均通过检查；真实应用端点完成临时音色导入、重命名、目录展示、导出、中文流式合成和删除。测试结束后清除了临时音色，日常选择未变更。

`scripts/smoke_voice_packs.py` 使用隔离用户目录和端口 3338 的临时 GPU worker，实际验证 Piper 英文、Qwen 中文 WAV、英文流式、导出再导入、音色切换和删除。测试不修改日常音色库；生成的音频与结果位于 `logs/voice-pack-smoke/`。

本机 GPU 验证：首个 Qwen 请求约 38.6 秒（包含冷启动），后续短句完整流式请求约 0.37–0.79 秒。这些是此机器的测试结果，不代表 CPU 或所有录音的耗时。测试使用已有 Jarvis 参考录音，未对任意第三方录音的音色相似度作保证。
